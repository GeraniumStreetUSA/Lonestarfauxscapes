# Brief for page-building agents (read before anything else)

Repo: `/Volumes/hermes_agent/websites/Lonestarfauxscapes`, app in `app/`. Several agents work in this checkout AT THE SAME TIME, each on its own pages.

1. Read `tasks/rebuild-page-rules.md` (hard rules) and `tasks/rebuild-templates.md` (page anatomy), then `app/src/pages/KitPage.tsx` and `app/src/components/page/*` (the kit you build with), `app/src/routes.ts` (your routes' titles, descriptions, breadcrumbs, `hasQuoteForm`), and `app/src/pages/HomePage.tsx` + `app/src/sections/*` (the quality bar).
2. Content source: each page's OLD live HTML in the repo root (`<slug>.html`), plus `CLAIMS.md`, `OWNER-NEEDS.md`, `docs/truth-audit.md`, `content/case-studies.json`, `content/case-studies/*.md`. Read the old page fully (ignore its nav, footer, scripts). Carry over its useful substance and its main H2 topics; drop every claim the rules forbid.
3. Files you may create or edit: ONLY those named in your scope. Every route already has a stub at `app/src/pages/routes/<slug>.tsx`; replace your stubs with real pages. Never edit `app/src/routes.ts`, `app/src/index.css`, `app/src/styles/page-kit.css`, `app/src/components/**`, `app/src/sections/**`, `app/src/data/site.ts`, `app/src/data/home-content.ts`, or another agent's files. If the kit is missing something you need, build it inside your own template file or your own CSS file and mention it in your report (I will promote it to the kit).
4. Your CSS: one plain CSS file named in your scope, imported by your template component (`import '../styles/<name>.css'`). Prefix your classes with your scope prefix. No `@layer`, no `@apply`.
5. Images: real photos only. Use `<Picture>` with names from `app/src/data/image-manifest.json`. To add a photo from the repo's `images/` or `public/` folders, add it to your own list file `app/scripts/images/<scope>.mjs` (same shape as the IMAGES entries in `app/scripts/make-images.mjs`) and run `cd app && npm run images`. Only use photos whose content you have checked (open them with the Read tool). Uncaptioned unless a documented Texas job.
6. FAQs: render with `FaqList` and add a `<script type="application/ld+json">` FAQPage node built with `faqSchemaNode` from `app/src/lib/faq-schema.ts` inside your page (visible questions only).
7. Checks: `cd app && npm run typecheck && npm test` as often as you like. Full builds ONLY through `sh scripts/build-locked.sh` (serialises builds between agents). Before reporting, a locked build must pass and your pages in `dist/` must each have one H1 and no em-dash (`grep -c $'—' dist/<page>.html` is 0).
8. Do not use git. Do not open a browser (I review every page at 390, 360 and 1440 myself). Do not start servers.
9. Report: pages done, claims you dropped (short list per page), photos used, anything you built that belongs in the kit, anything you could not do.
